# 配对式远程连接升级：逐条需求与验收约定

记录日期：2026-10-17（Asia/Shanghai）。状态：增强版开发中；尚未完成一小时验收。

用户补充约束：优先保留当前 MQTT＋SSH；无需注册账号、无需购买服务、无需自建服务器。替换底座必须先实测证明稳定性显著提升。在这些条件下，本轮选择继续增强当前链路，不部署 Tailscale。

## 用户要求逐条复述

1. 在云端开发当前公网 SSH 连接工具的增强版本，不以聊天建议代替实现和交付。
2. 现有远端、近端、MCP 通道、文件桥网站及其隧道继续运行；开发和验证不得与其冲突。
3. 为开发版另外运行一套近端和远端；采用独立程序目录、私密状态目录、身份、会话、主题、监听端口、进程和启动项名称。不得在同一会话上运行两个远端。
4. 查阅成熟远程接入服务的实际架构，再按当前公网接入、少数用户和设备规模选择方案，避免无必要的分布式基础设施。
5. 不增加需要用户购买、部署或维护的服务器。公网中继仍依赖第三方基础设施；不能把“不自建服务器”说成“不需要任何中继或协调服务”。
6. 保留仅公网、指定设备接入的范围，不新增局域网发现、子网路由或出口节点。
7. 首次接入类似 Parsec：远端展示配对码，近端输入配对码即可发起配对；不再要求每次粘贴整段连接块。
8. 配对成功后持久记住这台电脑和可信身份。普通断线、程序重启或临时中继故障不得清空配对、轮换身份或要求再次配对。
9. 近端保存默认目标，启动后自动连接指定的已配对主机；多设备时必须明确当前目标，不能连接任意可见设备。
10. 两端自动重连：网络中断、broker/中继断开、对端离线后重新上线时自动恢复，持续重试，无需用户重复复制粘贴。
11. 自动重试必须有指数退避、抖动、最大等待、单实例和重试状态；不产生重试风暴、重复隧道或重复弹窗。
12. 连接恢复必须重新验证固定设备身份、SSH 主机指纹和实际身份。身份改变、撤销和凭据丢失须明确提示，不能悄悄接受新主机。
13. 近端和远端都提供图形界面，展示配对、已配对电脑、默认目标、连接状态、最近错误、下一次重试和诊断入口。
14. 两端都有系统托盘入口；关闭界面后可以留在托盘，显式退出则停止该实例和恢复循环。区分“断开”“取消自动连接”“撤销配对”“退出”。
15. 两端都有“开机自启动”开关，修改后持久保存，下次启动仍保持。界面必须反映操作系统中的真实注册结果，注册失败不能显示已开启。
16. 自启动进入后台或托盘，不反复弹出终端、PowerShell 或浏览器。首次安装/配置时的界面与后台运行分开处理。
17. 区分“开机、尚未登录即可运行”和“用户登录后自动启动”。前者需要系统服务、权限和生命周期设计；后者不能冒称前者。
18. 提供真正落盘的日志系统：记录断开阶段、错误分类、重试次数、下次等待、配对/撤销事件、身份校验、进程退出和恢复结果；双端可关联定位。
19. 日志按大小/保留量轮转，避免无限增长；私钥、配对码、连接块、认证 token、命令内容和文件内容不得写入日志或 Git。支持本地查看和脱敏诊断。
20. 连通证明必须是实际 SSH 认证和身份探测，不能以 PID、监听端口、订阅成功或 MQTT PUBACK 替代。
21. 短暂丢包恢复维持有序字节流；连接已经失效时重建连接并明确报告旧会话失效，不假称旧 shell 或旧任务已恢复。
22. 自动恢复只处理连接层；断线后先核对任务结果，不自动重放部署、写入、删除、上传或数据库导入。
23. 调试持续到最终版本具备配对后自动记忆、指定主机自动重连，并完成至少一小时稳定性验收后，才算达到本阶段停止条件。
24. 一小时必须有实际持续探测、长连接、传输完整性和资源记录；历史 660 秒记录不能替代本次一小时记录。
25. 同时验证故障恢复：仅对开发实例注入近端退出、远端退出、中继连接丢失、临时不可达及进程重启；恢复后不重新输入配对码。不得断开用户整机网络或影响现有隧道。
26. 对真实 Windows 电脑的验证、云端隔离自测、无桌面 GUI 检查分别记录，不能相互冒充。未执行真实重启或托盘交互就不能宣称相应实机验收完成。
27. 修改集中在私有工作分支 `recovery/current-public-relay-mcp`；不得在 main 开发、推送 main 或合并 main。参考交接提交 `4c39dd0ad354bb1efebab4a6709cff372df88a24`；开始时远程工作分支已有后继 `4c05038`，在其上继续，保留重连纪律。
28. 不修改云环境配置，不安装或替换全局网络设施，不改变路由、代理或 CA 配置。应用自身的自启开关属于本次产品功能，但不得顺带修改其他程序的启动项。
29. 修复后更新应用源码、运行包、校验值和说明，验证后上传私有工作分支；不得公开源码、私密连接材料或原始运行日志。
30. 文档逐项对应实现和证据，未实现、未测试、测试中和通过必须如实区分。“最高级”按上述可验收能力落实，不作为无边界功能承诺。

## 已核对的现状

当前分支已有 `src/diagnostics.cjs`，将双端元数据按每份 2 MiB、3 份备份保存；因此不能笼统称完全没有日志。仍需核对用户实际运行的包是否包含该功能，并补齐产品界面的日志入口、生命周期和重连诊断。

`src/relay.cjs` 已有 MQTT 自动重连及协议 2 的接收端 ACK、重传和去重；固定约 3 秒 MQTT 重试不等于完整的指定主机 SSH/MCP 自动恢复。Skill 的人工执行纪律也不等于产品已经实现自动恢复。

当前独立便携包缺少本需求中的双端托盘、配对管理界面和经验证的自启动开关。本文件不将计划功能计作可用功能。

### 网络工程结论

本轮明确选择继续使用现有 MQTT WSS＋端到端 SSH，在独立开发实例中增强持久配对、每个已配对近端的独立中继会话、监管恢复、指数退避、双端托盘、自启动开关和落盘日志。无需账号、购买服务或自建服务器。Tailscale 的长期身份和自动恢复机制仅作设计参考，不再以账号授权为本轮前置条件。

每个远端最多保存 16 个配对链路，各自有独立 session/secret，避免多个近端互相触发实例重置；近端可记住多台主机，每次自动连接明确选中的一台。首次配对使用 128 位随机一次性码（32 个十六进制字符，分组显示），十分钟过期，凭据经 AES-256-GCM 认证加密交换；不把不安全的短数字密码当作成熟 PAKE 的替代。远端可撤销全部配对；近端移除本地记忆不冒称远端撤权。

公共 broker 的可用性不由本项目控制。因此验收结论只描述本构建在实测窗口内的连接、传输和自动恢复结果，不承诺免费公共服务的 SLA，不把一小时通过当作永不掉线。

### 无论底座如何都必须落实的设计

- 配对状态、连接状态、操作执行状态分离。配对确立长期可信设备；连接可反复重建；业务操作不自动重放。
- 记住设备公钥/指纹和默认目标，不把会过期的会话或随机隧道 URL 当设备身份。
- 如自行提供短数字配对码，采用经过审查的 PAKE/现有成熟配对机制及过期/限流/撤销；禁止直接将六位数字哈希成可离线猜测的共享密钥。
- 配对与撤销遵循认证闭环；断线不撤销授权，错误主机不自动降级信任。
- 有限状态机：未配对、待授权、连接中、已连接、等待重试、远端离线、身份异常、已暂停、已退出。永久性身份错误与可恢复网络错误分开。
- 两端使用单实例锁和应用私密状态；保存原子化，凭据使用系统凭据设施或平台可验证的文件权限保护；支持升级保留身份。
- 托盘 UI 和后台连接服务分离；登录自启和系统开机服务分别验证；开关失败可回滚并向界面显示实际状态。
- 开发实例仅结束自己确认为所有的进程，不做整机断网和整机服务重启，不修改现有生产实例身份、端口和数据。

## 一小时验收门槛

最终应用快照确定后，先完成配对/持久化/恢复故障测试，再运行连续至少 3600 秒公网健康窗口；最后一次影响应用行为的修改后重新计算窗口。测试结束时间以单调时钟和实际结果为准，不以计划时间为准。

| 验收项 | 必须记录的事实 |
| --- | --- |
| 隔离与身份 | 双端构建摘要、协议/底座、各实例归属、固定主机身份、实际 whoami/hostname；不保存凭据到结果文件 |
| 配对记忆 | 首次配对成功；重启两端仍识别同一设备；无需第二次复制连接块或输入配对码 |
| 指定主机 | 多设备/错误主机/撤销/指纹变化时不串机，不自动信任错误身份 |
| 自动恢复 | 每类故障的触发时间、恢复时间、失败阶段、重试次数及退避；证明旧操作没有再次执行 |
| 持续健康 | 至少 3600 秒的实际 SSH 探测；活跃与空闲长连接；恢复后的新连接单独统计 |
| 文件完整性 | 周期性双向传输及 SHA-256 核验，覆盖大文件、中文路径和错误返回 |
| 资源与日志 | 内存/句柄/连接数没有持续无界增长；错误落盘、脱敏和轮转有效 |
| 托盘与启动 | 双端托盘操作；开关开/关、应用重启后记忆、操作系统实际注册和启动验证；未重启系统不得填“真实开机通过” |
| 现有服务保护 | 测试前后原通道身份探测及现有服务只读检查；不重启原实例 |
| 证据边界 | 脱敏汇总可提交；原始日志和私密运行状态不提交；真实 Windows 和云端自测分别记载 |
